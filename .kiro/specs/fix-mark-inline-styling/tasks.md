# Implementation Plan

## Tasks

- [x] 1. マークハイライトプラグインのノード生成方式変更
- [x] 1.1 HTMLノードからカスタムMDATノードへの変換ロジック実装
  - テキストノード内の`==text==`パターン検出後、`type: 'html'`の代わりに`type: 'mark'`カスタムノードを生成する
  - `data.hName`に`'mark'`を設定し、remark-rehype変換で自動的に`<mark>`タグが生成されるようにする
  - `data.hProperties`にアクセシビリティ属性（role, class, tabindex）を設定する
  - 子ノードとしてテキストノードを配置し、親ノード（strong/emphasis）との入れ子関係を維持する
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 5.1_

- [x] 1.2 カスタム属性パースの移行
  - `{.class}`記法のパース結果を`data.hProperties.className`に設定する
  - `aria-label`属性のパース結果を`data.hProperties['aria-label']`に設定する
  - HTMLエスケープ処理をテキストノードの値に適用する（HTMLノード内での直接出力から変更）
  - _Requirements: 5.3, 5.4_

- [x] 1.3 エスケープ処理とエラーハンドリングの維持
  - `\==`エスケープシーケンスの処理を維持し、リテラル文字列として出力する
  - 空のハイライト（`====`）や不正なパターンは元のテキストをそのまま出力する
  - 入力長チェック（maxInputLength）とセキュリティモード処理を維持する
  - _Requirements: 5.2, 5.5, 6.3_

- [x] 2. キャッシュ機構の調整
- [x] 2.1 キャッシュ値構造の更新
  - キャッシュに格納する値を`type: 'html'`ノードから`type: 'mark'`カスタムノードに変更する
  - キャッシュキー形式は変更なし（text:className:accessibility:focusable）
  - キャッシュからの復元時に正しいノード構造が維持されることを確認する
  - _Requirements: 6.1, 6.2_

- [x] 3. ユニットテストの作成
- [x] 3.1 (P) 基本機能のテスト作成
  - 単独の`==text==`が正しく`mark`ノードに変換されることを検証する
  - `data.hName`と`data.hProperties`が正しく設定されることを検証する
  - エスケープ処理（`\==`）が正しく動作することを検証する
  - カスタム属性パース（`{.class}`、`aria-label`）が正しく動作することを検証する
  - _Requirements: 5.1, 5.2, 5.3, 5.4_

- [x] 3.2 (P) インラインスタイル併用のテスト作成
  - `**==text==**`（strong + mark）が正しい入れ子構造で変換されることを検証する
  - `*==text==*`（emphasis + mark）が正しい入れ子構造で変換されることを検証する
  - `` ==`code`== ``（mark + inlineCode）が正しく変換されることを検証する
  - `***==text==***`（strong + emphasis + mark）の3重入れ子が正しく変換されることを検証する
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 4.3_

- [x] 3.3 (P) エッジケースとエラーハンドリングのテスト作成
  - 複数のマークハイライトが同一親ノード内にある場合のテスト
  - 空のハイライト（`====`）がそのまま出力されることを検証する
  - inlineCode内の`==`がリテラルとして保持されることを検証する
  - 入力長超過時のスキップ動作を検証する
  - _Requirements: 1.3, 2.3, 3.2, 5.5, 6.3_

- [x] 4. 統合テストと動作確認
- [x] 4.1 Astroビルドでの統合テスト
  - 開発サーバーを起動し、テスト記事`mark-inline-styling-test`で動作を確認する
  - 各テストケース（strong+mark、emphasis+mark、code+mark等）が正しくレンダリングされることを確認する
  - 既存の`mark-highlight-test`記事が従来通り表示されることを確認する（後方互換性）
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 3.1, 4.1, 5.1_

- [x] 4.2 パフォーマンス確認
  - ビルド時間が従来比150%以内に収まることを確認する
  - 大量のマークハイライトを含む記事でのビルドが正常に完了することを確認する
  - _Requirements: 6.1, 6.2_
